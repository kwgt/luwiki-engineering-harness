# Markdown文書レビューガイドライン

報告書や設計書などのMarkdown文書について、レビューを伴う作成・改訂を行う場合の運用方法を記述する。

## 基本
- レビューの要否はユーザからの指示および設定された作業強度を考慮して決定し、レビューの粒度・深度は設定された作業強度に応じて調整すること。ただし、レビューが明示的に指示されている場合は省略しないこと。
- 原則としてレビューイがレビューシートを作成し、このレビューシートを中心にレビューを行う
- 対象文書の草案はレビューシートに子ページを作成し、このページに直接Markdownで記述する。レビュワーはこの草案ページのレンダリング結果でレビューを行う。
- 文書の改訂などの場合は、草案中の差分対象の箇所に引用の体裁で注記を記入する
- レビューサイクルを回す場合、Wikiのリビジョン管理機能を用いてレビューシートおよび草案ページの履歴管理を行う。ラウンドを進める場合は、新規ページを作成するのではなく同じページを更新することによりこれを行う。
- レビューの指摘を受けた草案の改訂は、レビュワーとの協議によって対応方針を確定した後に実施する。
- 各レビューラウンドでは、レビュー対象となる草案ページのリビジョンを明示し、レビュワーは当該リビジョンを対象としてレビューを行う。
- クローズ済みのレビューシートには議事録としての機能を持たせる。

## レビューシート仕様
トップレベルセクションに状態バナーを配置する。レビューサイクルを繰り返している場合はラウンド番号をここに記載する。
第二レベルセクションに以下の項目を設け記載する。

- 概要:
    - 文書の位置づけ・レビューの目的など概要情報を記載する。
    - レビューイがレビューシート起票時に記入する
- 対象文書:
    - 対象文書(草案)に対するページリンクおよび対象のリビジョンを記載する。
    - レビューイがレビューシート起票時に記入する
- 参考文書:
    - レビュー時に参考とすべき文書がある場合はその文書へのリンクを記載する。
    - レビューイがレビューシート起票時に記入する
- 要確認箇所:
    - レビューイから見た要確認箇所を箇条書きで列挙する(レビュワーが指摘時に項目を特定しやすいように番号付きとする)
    - レビューイがレビューシート起票時に記入する
- 指摘・コメント:
    - レビュワーがレビュー結果を書き込む領域
- 指摘への対応:
    - レビュー後の対応などのレビュー結果を受けたアクションを記入する領域
    - エージェントがレビューのまとめとして記入する

## レビューの手順
以下の手順でレビューを実施する。

1. レビューイ(通常はAIエージェント)がレビューシートを作成
2. レビューシートを受けて、レビュワーがレビューを行い指摘・コメント欄を記入
3. レビューシートの記入を受けてレビューイが指摘内容を分析し、対応方針を検討する。
4. レビューイとレビュワーが対話セッションを通じて対応方針を協議する。
5. 最終的な結論が出たらレビュワーが決済を行い、エージェントが指摘への対応を以下の観点でまとめて記入をおこなう。記入レベルは設定された作業強度を考慮して決定すること。
    - 指摘内容に対する最終的な対応方針
    - 対応する、対応しない、保留する、などの判断結果
    - 判断に至った理由
    - 文書に修正を反映した場合は、その内容
6. さらなる改訂や更新が必要な場合は、草案を更新し手順の1.からを繰り返す(ラウンド進行)。
    - ラウンド進行が行われる場合は、レビューシートの更新を行うこと。
    - このとき、未解決の指摘や継続して確認が必要な事項を除き、前ラウンドの各セクションの内容は原則として引き継がないこと。
