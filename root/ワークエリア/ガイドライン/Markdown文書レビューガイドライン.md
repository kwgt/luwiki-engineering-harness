# Markdown文書レビューガイドライン

報告書や設計書などのMarkdown文書について、作成・改訂に伴うレビューを行う場合の運用方法を記述する。

## 基本
- レビューの要否はユーザからの指示および設定された作業強度を考慮して決定し、レビューの粒度・深度は設定された作業強度に応じて調整すること。ただし、レビューが明示的に指示されている場合は省略しないこと。
- 原則としてレビューイがレビューシートを作成し、このレビューシートを中心にレビューを行う
- 対象文書の草案はレビューシートに子ページを作成し、このページに直接Markdownで記述する。レビュワーはこの草案ページのレンダリング結果でレビューを行う。
- 文書の改訂などの場合は、草案中の差分対象の箇所に引用の体裁で注記を記入する
- レビューサイクルを回す場合、Wikiのリビジョン管理機能を用いてレビューシートおよび草案ページの履歴管理を行う。ラウンドを進める場合は、新規ページを作成するのではなく同じページを更新することによりこれを行う。
- レビューの指摘を受けた草案の改訂は、レビュワーとの協議によって対応方針を確定した後に実施する。
- 各レビューラウンドでは、レビュー対象となる草案ページのリビジョンを明示し、レビュワーは当該リビジョンを対象としてレビューを行う。
- 以下のいずれかをもってレビューをクローズする。
    - レビュワーからレビュー合格の承認を得る
    - レビュワーからレビュー中断の指示を受ける
- レビューがクローズされた場合、エージェントは状態バナーにクローズを反映させる。この時、クローズの理由を簡潔に書き添えること。
- クローズ済みのレビューシートには議事録としての機能を持たせるため再利用してはならない。
- エージェントは以下の何れかの状態になるまで正本に対し草案の内容の反映を行ってはならない。また、レビューが中断された場合も指示がない限り正本への反映は行ってはならない。
    - レビュワーからレビュー合格の承認を得た
    - ユーザから正本への反映指示を受けた

## レビューシート仕様
トップレベルセクションに状態バナーを配置する。レビューサイクルを繰り返している場合はラウンド番号をここに記載する。
第二レベルセクションに以下の項目を設け記載する。

- 概要:
    - 文書の位置づけ・レビューの目的など概要情報を記載する。
    - レビューイがレビューシート起票時に記入する
- 対象文書:
    - 対象文書(草案)に対するページリンクおよび対象のリビジョンを記載する。
    - レビューイがレビューシート起票時に記入する
- 参考文書:
    - レビュー時に参考とすべき文書がある場合はその文書へのリンクを記載する。
    - レビューイがレビューシート起票時に記入する
- 要確認箇所:
    - レビューイから見た要確認箇所を箇条書きで列挙する
    - 要確認項目リストのアイテムにはレビュワーが指摘時に項目を特定しやすいようにIDを付与すること。
    - 要確認項目IDはシートをまたがった参照を許可する。
    - 要確認項目は草案中の対応個所を可能な限り明示すること。
    - レビューイがレビューシート起票時に記入する
- 指摘・コメント:
    - レビュワーがレビュー結果を書き込む領域
- 指摘への対応:
    - レビュー後の対応などのレビュー結果を受けたアクションを記入する領域
    - エージェントがレビューのまとめとして記入する

### 要確認項目IDのフォーマット
要確認項目に付与するIDは以下のように定める

```
R{{ラウンド番号}}-{{シート内での連番}}
```

## レビューの手順
以下の手順でレビューを実施する。

1. レビューイ(通常はAIエージェント)がレビューシートを作成
2. レビューシートを受けて、レビュワーがレビューを行い指摘・コメント欄を記入
3. レビューシートの記入を受けてレビューイが指摘内容を分析し、対応方針を検討する。
4. レビューイとレビュワーが対話セッションを通じて対応方針を協議する。
5. 最終的な結論が出たらエージェントが指摘への対応を以下の観点でまとめて記入をおこなう。記入レベルは設定された作業強度を考慮して決定すること。
    - 指摘内容に対する最終的な対応方針
    - 対応する、対応しない、保留する、などの判断結果
    - 判断に至った理由
    - 文書に修正を反映した場合は、その内容
6. 記入された指摘への対応の内容についてユーザが確認を行う。協議内容との不一致がなければ次のステップに進むことを指示する。
7. さらなる改訂や更新が必要な場合は、以下の手順でラウンドを進行させる。
    A. 確定した対応方針に基づいて草案を更新する。
    B. 次のラウンドでレビュー対象となる草案のリビジョンを確定する。
    C. レビューシートの更新を行う
        - ラウンド番号を進め、対象リビジョンを更新する。
        - 未解決の指摘や継続して確認が必要な事項を除き、前ラウンドの各セクションの内容は原則として引き継がない。
    D. 更新したレビューシートをレビュワーに提示し、手順2から繰り返す

修正を要する指摘・コメントを受けた場合はラウンドを進め修正を行うことになる。最終的にレビュー合格の承認をレビュワーから受けるまでラウンドを繰り返す必要がある(このため最終ラウンドの草案は完成版と内容が同じになる)。
